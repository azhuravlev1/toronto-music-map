# Toronto Music Map – agent notes

Static site: open `index.html` directly in a browser (no build, no server).
Map = Leaflet + CARTO light tiles (OpenStreetMap data). No API keys.

## Files

| File | What |
|---|---|
| `data/venues.js` | `window.VENUES` – venue list (id, name, capacity, type, colours, website). Hand-editable. |
| `data/transit.js` | `window.TRANSIT` – TTC + GO geometry. Generated by `tools/build_transit.py`. |
| `data/events.js` | `window.EVENTS` – upcoming events. Generated by `tools/reload.py`. Do not hand-edit. |
| `tools/research/*.json` | Raw research output for a reload (one file per batch of venues). |
| `history/past_events.txt` | Archive of events that have already happened (append-only). |

## The "reload" procedure

When the user asks to **reload / update the map**:

1. Window = today .. today + 20 days (21 days inclusive, local Toronto time).
2. Delete old files in `tools/research/`.
3. For every venue in `data/venues.js`, research real events in the window
   (venue site, Ticketmaster, Live Nation, AXS, Showclix, Eventbrite, Resident Advisor,
   Songkick, blogTO/NOW listings…). Split venues into batches and run research
   agents in parallel; each writes `tools/research/<batch>.json`.
4. Run `python3 tools/reload.py`. It archives past events from the current
   `data/events.js` into `history/past_events.txt`, merges all research files,
   drops anything outside the window, dedupes, and writes `data/events.js`.
5. Report venues where nothing could be found / verified.

The page itself hides events dated before today, so between reloads past
events disappear automatically every day. `python3 tools/reload.py --prune-only`
archives past events without merging new research.

## Research file schema (`tools/research/<batch>.json`)

A JSON array of event objects:

```json
{
  "venue": "massey-hall",            // id from data/venues.js
  "date": "2026-11-14",              // YYYY-MM-DD (event start, local time)
  "title": "Feist",                  // artist(s) / event name, short. Headliner first; " + " between co-headliners; supports optional " w/ " for openers
  "url": "https://...",              // the event's own page (ticket page or venue event page); venue listings page only as a last resort
  "type": "concert",                 // see types below
  "time": "20:00",                   // optional, 24h
  "emoji": "🏒"                       // optional override of the type emoji
}
```

Types (anything other than `concert` is shown with a distinct colour + emoji):

`concert` (any live music incl. classical, opera, jazz, open-stage jams) ·
`party` 🪩 (DJ / club night) · `comedy` 😂 · `theatre` 🎭 (plays, musicals) ·
`dance` 🩰 · `sports` 🏟️ (set `emoji`: 🏒 🏀 ⚾ 🥍 🎾 🤼 ⚽) · `film` 🎬 ·
`talk` 🎙️ (lectures, podcasts, panels) · `family` 🧸 · `festival` 🎪 (markets, fairs, expos) · `other` ✨

Rules: only real, verified events – never invent. If a venue lists a recurring
weekly series (e.g. a jazz jam every Monday) include each occurrence with the
series page as the URL. One object per event; multiple events per venue per
day are fine.
